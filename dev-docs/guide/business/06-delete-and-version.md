# 删除与版本

## 版本

内容行的 `version` 从 0 开始。更新语句带 `WHERE version = ?`，成功时加一。版本不对返回 409，调用方用刷新后的版本重试。

同一 `requestId` 配上同一命令体会重放第一次的结果，不会再加版本。同一 `requestId` 配上不同命令体返回 409。

图片和视频任务没有行版本。删除不走这条乐观锁。修改仍用修订表里的最大版本。

## 软删顺序

同一事务内完成，子行先于父行：

| 操作 | 顺序 | 父行 |
|---|---|---|
| 删除剧本分集 | 场次，然后分集 | 剧本只更新集数和版本 |
| 删除剧本场次 | 场次自己 | 分集更新场次数 |
| 替换剧本原文 | 全部场次，然后全部分集 | 剧本改原文并加版本 |
| 删除分镜集 | 镜头，场次，分镜集 | 分镜加版本。分镜集写 `deleted_id` |
| 删除分镜场次 | 镜头，场次 | 分镜集加版本 |
| 清空分镜 | 镜头，场次，分镜集 | 分镜保留并加版本 |
| 清空分镜集 | 镜头，场次 | 分镜集保留并加版本 |
| 删除主资产 | 全部子资产，然后主资产 | 无 |
| 删除子资产 | 子资产 | 主资产加版本；封面命中则清空封面 |
| 删除图片或视频任务 | 条目，然后任务 | 无修订。状态必须已结束 |

每次软删的子行都有一条 revision。修订的 `changedFields` 按字母序保存。

## 为什么子行也要修订

只修订父行时，历史里看不到哪一条镜头或场次被删了。Java 的资源变更按行记录。Go 的级联沿用这个粒度。
